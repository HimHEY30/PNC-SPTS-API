# Prompt‑Engineer for Postman – PNC‑SPTS‑API

## Overview
This guide helps **non‑technical stakeholders** (Department Admin, Teachers, IT Department, Students) use the **Postman collection** included in this repository to interact with the NestJS API.  Each folder in the collection mirrors a stakeholder group and contains ready‑to‑run requests with example payloads.

---

## 1. Import the collection
1. Open **Postman** (desktop or web).
2. Click **Import → Upload Files** and select `postman_collection.json` located in the same `src/` folder.
3. The collection will appear as *PNC‑SPTS‑API – Stakeholder Collection*.

## 2. Set up environment variables (optional but recommended)
| Variable | Example value | Description |
|----------|---------------|-------------|
| `BASE_URL` | `http://localhost:3000/api` | Base URL of the NestJS API. Adjust if the service runs on a different host/port. |
| `API_KEY` | *(your JWT or API key)* | Authentication token; leave empty for open endpoints. |

Create a new **Environment** in Postman, add the variables above, and select the environment before sending requests.

## 3. Folder structure & purpose
| Folder (Postman) | Stakeholder | Typical actions | Example endpoint |
|-------------------|------------|----------------|-------------------|
| **Department Admin / Owner / Sponsor** | System governance & reporting | Pull usage statistics, generate audit reports, configure organization settings | `POST {{BASE_URL}}/admin/report` |
| **Teachers / Primary Users** | Daily follow‑up recording | Create or update daily class follow‑up notes | `POST {{BASE_URL}}/teachers/follow-up` |
| **IT Department / Technical Owner** | Deployment & maintenance | Health‑check services, trigger restarts, manage DB migrations | `POST {{BASE_URL}}/it/health` |
| **Students / Subjects (Phase 2)** | Future self‑service access | List subjects, enrol in courses, view personal progress | `GET {{BASE_URL}}/students/subjects` |

Each folder contains a single request (or more if you expand it later). The request names are self‑descriptive.

---

## 4. Using a request
1. **Select the folder** that matches your role.
2. Click the request (e.g., *Generate System Report*).
3. Review the **Headers** – `Content-Type: application/json` and `Authorization: Bearer {{API_KEY}}` are added automatically.
4. **Edit the body** if you need different data; example JSON payloads are pre‑filled (see Section 5).
5. Press **Send** and inspect the response pane.

## 6. Extending the collection
If you add new API endpoints, follow these steps:
1. Open the collection in Postman, click **Add Request** inside the appropriate folder.
2. Fill in method, URL, headers, and body.
3. Export the updated collection (`Export → Collection v2.1`) and replace the `postman_collection.json` file in this repo.
4. Commit the changes.

## 7. Troubleshooting
- **401 Unauthorized** – Verify that `API_KEY` is correct and not expired.
- **404 Not Found** – Ensure the endpoint path matches the NestJS controller (check `src/modules/*`).
- **500 Internal Server Error** – Look at the NestJS logs (`docker logs nestjs`) for stack traces; migration errors (P3009) must be resolved before the API works.
